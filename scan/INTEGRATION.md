# Keep Scan installed after a daily rebuild

The public site is regenerated by `card_app/build.py` from `index.tpl.html`. That generator is not in this repository. A normal rebuild rewrites `index.html`, `sw.js`, `data.js`, `version.json`, and `h/`. It will remove the scan button unless the generator keeps the hook below.

The scan program itself lives in `scan/`. Do not delete that directory during a rebuild. It does not contain user photos.

## Required hook

In `index.tpl.html`, immediately before `</body>`:

```html
<!-- card-scan:start -->
<script type="module" src="scan/boot.js"></script>
<!-- card-scan:end -->
```

In the service-worker precache list inside the generator, keep these paths and do not add the multi-megabyte OCR files:

```text
scan/boot.js
scan/engine.js
scan/lookup.js
scan/image.js
scan/scan.css
scan/verified-prices.json
```

`scan/boot.js` only adds a Scan button and a hidden section. Lists, the phone/PC toggle, charts, and the existing service-worker rules stay in the generated page.

OCR files under `scan/vendor/` are fetched the first time someone presses **Read text**. They are cached by the existing same-origin fetch handler after that. Putting them in the install precache makes installation fail or slow if one file 404s.

## Safety net

From the site root, after `build.py` writes `index.html` and `sw.js`:

```bash
python3 scan/tools/integrate.py
python3 scan/tools/integrate.py --check
```

`integrate.py` is idempotent. It inserts the script tag if it is missing and appends the precache paths if they are missing. It does not change the cache name, and it leaves the cross-origin and non-GET guards in place.

`build.py` can call it:

```python
import runpy
runpy.run_path("scan/tools/integrate.py")
```

Run that with the site root as the current directory, after the HTML and service worker are written, and without deleting `scan/`.

## Optional verified grades

`data.js` has ungraded, PSA 9, and PSA 10 guide figures for many rows, and no PSA 5–8. The scanner does not invent those.

When a free local research script has a real sold or guide figure, write JSON in this shape and run:

```bash
python3 scan/tools/export_verified_prices.py /path/to/verified-grades.json
```

The script also reads these files when they exist:

- `/workspace/ygo_cards/verified-grades.json`
- `/workspace/mtg_cards/verified-grades.json`
- `scan/verified-input.json`

A grade is copied only when it already has a positive price, a 3-letter currency, a source name, and `observed_at`. Optional `sales_count` must be a non-negative integer. Optional `source_url` must be `http` or `https`. Price `0`, a missing source, and unknown grade names are rejected and listed. PSA 7 is not filled from PSA 8. The script does not scrape and does not call a model.

If those tracker files are absent, the exporter leaves `scan/verified-prices.json` unchanged.

This feature is not live for visitors until this branch is merged, the generator keeps the hook, and the deployed site is checked in a browser.
